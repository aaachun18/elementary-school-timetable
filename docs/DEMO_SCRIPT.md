# 面試示範腳本(5–8 分鐘)

照著走即可完成一輪現場示範。每一步都有「操作」「預期畫面」「可講的重點」。本腳本以 `scripts/seed_test_data.py` 建立的「示範國小」為準(2026-10-31 依目前程式更新);改版前依賴 `[SEED]` 舊資料、v4/v11 版本與重置腳本的舊腳本已移除。

> 自動排課每次使用新的 seed,排出的課表都不同,所以下面不寫死「哪一格是哪一堂課」;需要指定某一格時,以現場課表為準挑選。

---

## 準備(示範前做一次)

1. 啟動系統(擇一,見 README):`docker compose --profile full up --build -d`,或本機開發流程(後端 `python -m uvicorn`、前端 `npm run dev`)。
2. 建立示範資料(在專案根目錄、已啟用虛擬環境):`python scripts/seed_test_data.py`。**不要加 `--run`**,示範時現場排課。示範國小已存在時腳本會停止;要重來請先重設開發資料庫。
3. 帳號(密碼都是 `demo-pass-123`):系統管理員 `admin`、教學組長 `coordinator`、一般老師 `teacher01`–`teacher10`。
4. 示範資料:115 學年度第 1 學期、一到六年級各一班(一年甲班…六年甲班)、10 位老師、10 個預設科目;國語文由各班對應的老師授課(一年甲班王老師…六年甲班吳老師),自然科學與藝術是 `2+1` 連堂並指定自然教室/藝術教室,其他課原班上課;一筆「尚未排課」的排課紀錄(沒有設定導師班級,示範時在精靈第 2 步指派)。

### 示範前檢查(一分鐘)

- 打開 `http://localhost:5173` 看得到公開首頁(一定要用 `localhost`)。
- 以 `coordinator` 登入,「排課紀錄」只有一筆「尚未排課」的紀錄。
- 前一次示範產生的紀錄(自動排課、手動排課、複製)都已刪除,或乾脆重建資料庫。

## 開場:公開首頁與登入(約 30 秒)

- **操作**:打開 `http://localhost:5173` →「登入」。
- **預期畫面**:首頁有主視覺、課表截圖與四張功能卡片(排課精靈、自動排課與衝突檢查、手動調整與即時重新檢查、排課紀錄與發布)。登入頁左側是品牌區(漸層、淡格線、迷你課表插圖),右側是「歡迎回來」表單;把視窗縮到 768px 以下,品牌區會隱藏。
- **可講的重點**:登入頁的裝飾全部是 CSS 與 SVG,沒有新增套件或字體;文字對比(包含 85% 透明的副標)由 vitest 檢查,原本的主色上副標只有 3.88,所以背景改深一階。

## a. 系統管理員(約 30 秒)

- **操作**:以 `admin` 登入。
- **預期畫面**:直接進「學校管理」,看得到示範國小;導覽列只有「學校管理」「帳號管理」。「帳號管理」有序號、老師依姓名筆畫排序;左邊的角色下拉選「教師」只列一般老師;搜尋框輸入「王」按放大鏡,只剩王老師,再按「顯示全部」回到全部帳號。
- **可講的重點**:系統管理員只管學校與帳號,完全讀不到排課資料(後端 403);身分證字號的搜尋在後端做,因為前端只拿得到「有沒有填」,拿不到號碼。

## b. 開始排課精靈(約 2 分鐘)

- **操作**:登出,以 `coordinator` 登入 →「開始排課」。系統會回到那筆尚未排課的紀錄。依序看過 6 個步驟:
  1. **學年度與學期**:115 學年度第 1 學期(紀錄建立後學期固定,這一步只能看)。
  2. **教師設定**:10 位老師都已勾選,每週 8–20 節;點某位老師的「不可排時段」,以課表格式勾選。示範資料沒有設定導師班級:每個班都要有導師才能下一步,依序指派(建議與國語文的指定老師一致:一年甲班王老師、二年甲班林老師、三年甲班陳老師、四年甲班李老師、五年甲班張老師、六年甲班吳老師);國小選定導師時,會把該班國語文、數學的指定老師設為導師。導師班級的下拉選單可以打字搜尋。
  3. **年級與可排節次**:點「一年級」的「設定可排節次」,看預設的低年級節次。
  4. **科目需求**:選「三年甲班」,科目依「國語、英、數、生活、美勞、自然、社會、藝術、音樂、健康、體育、綜合」排序;國語文由導師授課,自然科學是 `2+1` 連堂並指定自然教室。指出「複製此教室設定至所有同年級班級」與連堂複製按鈕。
  5. **共同排課**:說明可以把同年級幾個班的同一科合併一起上(示範資料沒有設定)。
  6. **確認並排課**:「排課前檢查」沒有問題 →「自動排課」。
- **預期畫面**:排課成功,紀錄變成「自動排課」。
- **可講的重點**:
  - 引擎是自己寫的前向檢查搜尋:每放一堂課就刪掉其他課因此不能用的候選,卡住就依 Luby 數列換個順序重來,90 秒上限;每次用新的 seed,所以每次課表不同。
  - 15 條 Hard Constraint 全部滿足之後,才依三條偏好調整:國語數學排第 1–2 節、體育避開第 1、4、5 節、國小全日最後一節排活動性課程。

## c. 課表與自動檢查(約 1 分鐘)

- **操作**:「檢視課表」→ 依班級選「三年甲班」,再切到「依教師」「依教室」看看。
- **預期畫面**:標題下方的檢查標籤一進頁面就自動檢查,通常是綠色「無衝突」。三年甲班的國語、數學多在上午前兩節;自然科學的 2 節連堂在同一天相鄰、以左緣細條相連,課表上註記「自然教室」;依教室檢視列出同一格所有使用這間教室的班級。
- **可講的重點**:檢查與排課用同一套 Constraint 類別;檢查只回報、不阻擋——手動調課常需要暫時違規的中間步驟。

## d. 手動調整:拖曳、對調、連堂、換教師(約 2 分鐘)

- **操作**:「手動編輯課表」→ 點一下三年甲班的某一堂課(或開始拖曳它),先看課表上的標示。
- **預期畫面**:圖例「可放 / 衝突 / 可對調」;可放的空格淺綠、會產生新問題的格子淺紅、可以安全對調的課淺藍(⇄)。
- **操作**:
  1. 把這堂課拖到一格淺藍的課上(依班級檢視拖到有課的格子就是對調)→ 預覽「沒有新增問題」→ 確認。
  2. 把自然科學的 2 節連堂拖到另一天的某個位置,落點上若有本班的其他課也可以放下。
  3. 點一堂國語,在上方工具列的教師下拉輸入老師名字的一個字搜尋,改成另一位老師 → 預覽 → 確認。
  4. 「儲存課表」。
- **預期畫面**:每次確認前都先看到預覽(這次會新增/解決哪些問題);連堂預覽會列出被換到連堂原位的課;換教師後整門國語都換人;儲存後多出一筆「手動排課」紀錄(原本的自動排課紀錄不變)。
- **可講的重點**:
  - 候選標示與預覽是同一套判定(後端 `move-candidates` 一次試算每一格),只提示、不阻擋。
  - 連堂放寬:擋路的本班課換到連堂空出來的時段,放不進去才拒絕;同樣節數的兩組連堂照舊整組對調。
  - 換教師以整門課為單位,同時更新這筆紀錄的指定教師;同一班同一科目只能一位老師是 H15。
  - 手動編輯改的是背景的暫存副本,「儲存課表」才落地,離開頁面就丟棄。

## e. 發布與一般老師(約 1 分鐘)

- **操作**:在剛儲存的課表按「發布此課表」→ 確認。登出,以 `teacher01` 登入。
- **預期畫面**:一般老師只有「首頁」與「課表」,看得到剛發布的課表,沒有編輯入口,也沒有檢查標籤。
- **可講的重點**:每學期最多一筆已發布;發布新的一筆時舊的一筆自動取消發布、回到原本的狀態;也可以直接「取消發布」。權限的真正邊界在後端:一般老師呼叫任何寫入端點都是 403,只讀得到已發布的紀錄。

## f.(選用)失敗示範(約 1 分鐘)

- **操作**:以 `coordinator` 到「排課紀錄」→ 該筆紀錄「檢視排課設定」→「複製此次排課設定」,在新的紀錄的「年級與可排節次」把某個年級減到只剩幾節 →「確認並排課」。
- **預期畫面**:排課前就說明「某班每週要上的課多於年級開放的節次」,並連結回到要修正的步驟。
- **可講的重點**:九類靜態預檢不用搜尋就能證明無解;引擎的失敗訊息都是同一個 `ConstraintViolation` 格式,前端轉成中文並指出要去哪一步修。

## 面試常被問的問題與簡短回答

以下回答取自 `docs/SYSTEM_DESIGN.md`(括號內為章節或決策編號)。

- **為什麼約束引擎要獨立於框架?**
  `scheduling_engine/` 沒有任何一行 import SQLAlchemy 或 FastAPI,只吃、吐純 Python dataclass。224 個引擎測試不需要資料庫;開發演算法時一次都不用啟動 API(第 2 節)。

- **為什麼從 Backtracking 換成前向檢查?**
  每班時段全滿的學期,真正出錯的往往是很早以前的選擇,Backtracking 只撤回最近幾步修不到它;前向檢查提早刪除不能用的候選、每步挑最受限的單位,卡住就換順序重來(決策 45)。

- **Soft Constraint 怎麼保證不破壞合法性?**
  搜尋只負責產生合法課表;最佳化每一步都重新檢查所有即時 Hard Constraint,只有總分提高而且仍然合法才接受(第 5.4 節)。

- **為什麼檢查只回報、不阻擋?**
  手動調課常需要「先把 A 移到 B 的位置,再把 B 移走」這類中間步驟,中間狀態必然暫時違規;每次寫入就拒絕會讓這種調整做不下去(決策 15)。

- **排課紀錄怎麼避免互相影響?**
  v3 起每筆紀錄各自保存一整份設定與課表;手動編輯在暫存副本上進行,儲存才落地(第 0.3 節)。

- **token 與權限邊界?**
  登入時把 role 放進 JWT,前端只解碼來決定畫面(不驗證簽章);真正的檢查全部在後端:排課資料只有教學組長能寫,系統管理員讀不到排課資料,一般老師只讀得到已發布的紀錄,每個查詢都依學校過濾(第 3.6 節)。

- **已知限制與下一步?**
  Soft Constraint 只有三條、科目以名稱判定;手動調整沒有復原;前端沒有元件層級的自動化測試(第 10 節)。
