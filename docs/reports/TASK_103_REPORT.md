## 1. 手動調整拖曳放下無反應

### 重現方式
- 用 Chrome DevTools Protocol 的拖放事件（`Input.dispatchDragEvent`）自動測試，也在有畫面的 Chrome 上用 Windows `SendInput` 做真正的滑鼠拖曳。使用者同意暫時接管滑鼠。
- 測試資料是紀錄 #44（手動排課）。每次都進入「手動編輯課表」，只預覽、不存檔，結束時「放棄修改」。測試後確認沒有殘留暫存副本。
- 測試範圍：依班級／依教師／依教室 × 每一個班級／老師／教室 × 一般課／連堂／對調。Vite dev（IPv6 `localhost:5173`）和 Docker 打包版（IPv4 `localhost:5173`）兩個版本都測了。
- 逐段記錄：`dragstart` / `dragover` / `drop` / `dragend` 的順序、`defaultPrevented`、`dropEffect`、拖曳資料、放開時游標下的元素，以及 API 呼叫。

### 逐段檢查結果
- `dragover` 在可以放的格子有 `preventDefault`。
- `drop` 一定在 `dragend` 之前觸發，`dragend` 不會先清掉拖曳狀態。
- 綠框與「移到這裡」是 `pointer-events-none`，不會攔截事件。
- 移動 API（`move-lesson` 的 dry run）與預覽都正常，console 沒有錯誤。
- 近期的改動（定位高亮、自動重新檢查、停用處理）都沒有改到拖放邏輯。
- **回報的確切情境沒有完全重現**：游標停在綠色「移到這裡」上放開，在各視角都會跳出預覽。

### 根因（實測確認的兩個缺陷）
1. **操作途中版面位移**，讓按下或放開的位置落到別的元素上：
   - 開始拖曳時，每個有課的格子底下會多出一條虛線條，整張課表的列變高。實測目標格往下移 30–100px。
   - 游標停在有課的格子時，「移到這裡」會撐高那一格。
   - 存檔後的成功訊息、「無法放在這裡」和「正在預覽…」都放在課表上方。成功訊息 4 秒後消失時，課表整體上移約 36px。
   - 實測：存檔後約 4 秒去按下一堂課，按下的瞬間課表上移，按到格子空白處，瀏覽器變成「選取文字」（`selectstart`），拖曳根本沒開始。拖曳中版面位移時，放開點落在午休等不能放的格子上，`drop` 不會觸發，畫面上什麼都沒有。
   - 提示訊息在課表上方，頁面往下捲時也看不到。
2. **放下時默默不處理**：
   - `edit.disabled` 為 true（上一個預覽或儲存還在處理）時，`drop` 處理直接 return，格子卻仍顯示綠色。
   - 讀不到拖曳的課程時，程式會走到「放入未排入課程」的分支，而這時沒有選中的卡片，結果什麼都不做。

### 受影響的視角／情境
- 三種視角都會受影響，一般課與連堂都是。存檔後立刻再拖，以及課表較長、頁面往下捲時最容易遇到。
- 對調（拖到另一堂課上）比較不受影響，因為目標是課程按鈕本身。

### 修法
- 編輯模式下，有課的格子一律保留虛線條的高度（`DROP_STRIP_SPACE`），開始拖曳不再改變列高。
- 「移到這裡」和不能放的原因改成疊在格子底部（`absolute`），不佔空間。
- 成功、無法放置、預覽中這類短暫提示，改為固定在視窗下方（`TOAST_REGION`）。出現或消失都不推動課表，捲到哪裡都看得到。錯誤訊息與「已選取」列維持原位。
- 放下時不能處理的情況，改由 `ignoredDropReason()` 給出原因，以「無法放在這裡：…」顯示，例如「上一個動作還在處理中，請稍候再拖曳一次」、「沒有認出拖曳的課程，請再拖曳一次」。
- 「放入卡片」的分支只在真的有卡片被拖曳時才走。

### 修正後驗證
- 真實滑鼠：存檔後立刻再拖（包括原本失敗的時間點），一般課與對調 4/4 成功。
- CDP：依教師／依教室 × 每位老師／每間教室 × 一般課／連堂，全部開啟預覽或顯示原因。開始拖曳後目標格不再移動。修正前有 5 組以上是完全沒反應。
- 依班級 × 一般課／連堂／對調全部正常。原本可用的同視角移動、對調、連堂對調都沒有受影響。

### 追加修正（使用者回報「拖曳到任何方格仍出現：無法放在這裡…」之後）
- 使用者確認提示內容是「沒有認出拖曳的課程」，**主因因此確認**：
  - 格子上的綠色「移到這裡」是依頁面自己記住的拖曳中課程（`dragging`）畫的。
  - 但 `drop` 只讀瀏覽器的拖曳資料（`dataTransfer` 的 `text/plain`）來找是哪一堂課。
  - 在使用者的 Chrome 裡，放下時讀到的資料對不上任何一堂課，所以綠色提示正常、放下卻沒有作用。
  - 在全新設定檔的 Chrome 裡讀得到，所以之前的自動化與真實滑鼠測試都重現不出來。
- 修法：放下時以拖曳開始時記住的課程為準，拖曳資料只當備援（`utils/lessonDrop.ts` 的 `pickDraggedLesson()`）。這樣綠色提示和放下用的是同一個來源。
- 依使用者要求，拿掉放下後的所有原因提示：上次新增的兩種，以及連堂被擋下時原本的「無法放在這裡：…」。拖曳中，格子上「移到這裡」和不能放的標示保留；點選流程的提示不變。
- 驗證：讓頁面的 `getData` 一律回傳空字串，模擬使用者的環境。
  - 一般課 15/15、對調 14/14、連堂 7 次都正常開啟預覽。
  - 另外 4 次連堂是連堂規則本來就不允許的位置，拖曳中格子上已顯示原因，放開後不動作。
- 測試：`lessonDrop.test.ts` 以 `pickDraggedLesson` 回歸測試取代原本的 `ignoredDropReason` 測試，後者對應的功能已依要求移除。
- 前端 48 個檔案、525 個測試通過，`tsc` 沒有錯誤，oxlint 維持 2 個警告。
- **你那邊要重新 build 前端容器才看得到這次修正**：你現在用的是 Docker 打包版（IPv4 `localhost:5173`）。
